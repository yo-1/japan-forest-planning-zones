# 全国の細い隙間の補修

N03原典は変更しません。市町村の所属を確認できる箇所だけを市町村の派生版で
補修し、所属が不明でも両側が同じ森林計画区に属する隙間は、計画区の集約後に補修します。
広域流域は、補修済み計画区から再集約します。

## 検出と補修

`scripts/repair_narrow_gaps.py` は、幅を基準にした膨張・収縮で追加候補を検出します。
閉じた穴は内部リングを直接検査し、幅の条件を満たしたリングだけを取り除きます。
極端に細い穴は差分演算で消失することがあるため、閉じた穴の検出を差分演算に依存させません。
リングの削除では外環と残す内部リングの座標をそのまま保持します。
この処理結果で全体を置き換えず、採用した追加部分だけを原形状に合成します。
面積1㎡を超える細長い穴、パーツ間の隙間、海岸へ抜ける隙間も対象です。

試験幅は **0.001m** です。配布ビルドでは補修を既定で実行せず、`--gap-width-m`を明示したときだけ試験します。これは、従来の記録にあるサブミリの座標ずれを調べるために
こちらで置いた仮定です。全国すべての問題を解消できる値とは確定していません。
距離・面積は、各計画区の中心緯度を使った局所平面への換算値です。全国共通の厳密な測量距離ではありません。

候補の周囲の98%以上が同じ計画区の既存境界に接すること、幅の半分強の内向き
バッファーで広い内部が残らないこと、他の計画区や未割当地物に重ならないことを確認します。
形状だけで実在の細い水域を完全に区別できないので、基準幅を大きくするときは候補の確認が必要です。
狭い入口だけが閉じて大きな水域が囲まれる場合は、幅の検査で採用しません。

補修は追加のみです。図形演算の数値残差について、計画区あたりの減少面積が
0.0001㎡を超えたら停止します。0.0001㎡以下を数値誤差として扱うのは、こちらで置いた基準です。
不正形状も停止条件です。異なる計画区間の隙間を勝手に割り当てません。

`gap_repair_audit` レイヤには追加候補の形状、計画区コード、採否、面積、周長、
平均幅の参考値（2×面積÷周長）、既存境界に接する割合を記録します。
このレイヤは検出できた候補の台帳です。幅の基準を超えて検出できなかった全隙間の一覧ではありません。
`review_boundary`、`review_broad`、`review_other_area` は要確認として補修しません。
数値変換で候補が不正形状になった場合は `review_invalid` とし、自動補修しません。
合成で元形状が減る箇所は `review_result_loss`、合成結果が不正なら
`review_result_invalid`、別パーツが増える場合や原形状の面積を含まない追加だけのパーツが残る場合は
`review_result_fragmented`、既存パーツに接しない候補は `review_detached` として残します。
隙間に接するパーツだけを合成し、離れた小島等のパーツは元の座標のまま保持します。
`gap_residual_review` には、補修後に残る閉じた穴を記録します。実在の水域も含むため、
すべてを不具合とは扱いません。外側へ開いた未検出の隙間は、この穴一覧には含まれません。

## 市町村の所属が確認できる修正

`--municipality-patches` には、EPSG:6668を明示したGeoJSONを指定します。
各追加地物に `source_fid`、5桁の `municipality_code`、`approved: true`、
判断根拠を記した `evidence` が必要です。最近傍や接触長で市町村を推測しません。
原典由来の入力を保持し、別ファイルに補修版を書きます。指定がなければ市町村形状は変更しません。

```json
{
  "type": "FeatureCollection",
  "crs": {"type": "name", "properties": {"name": "EPSG:6668"}},
  "features": []
}
```

## 実行

```bash
python scripts/build_provisional_aggregates.py INPUT.gpkg OUTPUT.gpkg --gap-width-m 0.001
python scripts/build_review_release.py --output output/review_gap_repair --gap-width-m 0.001
python scripts/finalize_closed_gap_repairs.py PREVIOUS_REVIEW.gpkg FINISHED_REVIEW.gpkg --gap-width-m 0.001
```

最後のコマンドは、膨張・収縮だけで生成済みの確認用データに、内部リングの直接検査を追加するものです。

元の区域所属・地物数（計画区158、広域流域44、未割当20）は変えません。
補修スクリプトはPython 3.10以上とShapely 2.1.2が必要です。Python 3.9のCIでは
対応表等を検査し、Shapelyを使う補修検査は未実行として扱います。
計画区と広域流域を別々に面積基準で穴埋めする従来の公開処理は呼び出しません。
旧 `drop_tiny_rings.py` は既存成果の再現用に保持します。

## 完了の判定

人工データで閉じた長い穴・海岸へ開いた隙間の補修、水域・小島の保持、他区域との
競合の除外、再実行時の安定性を検査します。市町村修正は根拠不足・コード不一致・
他市町村との重複を拒否します。
全国実データでは追加・減少面積、採否件数、158区から44流域への形状一致、
新たな重複、不正形状を検査します。利用者指摘箇所のQGISでの表示確認は別途行います。
新しい成果物は確認用です。公式の市町村界・森林計画区境界を確定するものではありません。
