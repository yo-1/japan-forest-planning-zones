### 区別が失われた座標と無効箇所

閉点・巡回隣接を除き、参照では異なる非隣接頂点が、GDBでは完全に同じ座標になる組を検索しました。

|---|---:|---:|
| 計画区 | 37 | 20 |
| 流域 | 51 | 16 |

無効となった全16計画区・全11流域で、新たな非隣接座標一致を確認しました。無効リングと理由、元の座標・GDB座標・位置番号を全件結果に保存しました。さらに88組の[診断位置GeoJSON](diagnostic-coincident-locations.geojson)を作成しました。これは**AIの座標比較で得た位置であり、Esriが返したエラー位置ではありません**。計画区と流域で同一地点が重複する場合もあり、88組を88個の独立地点とは呼びません。

025ではring 2023のpos 54180と54182（0始まり）が、参照で `(139.968179805,39.880223054)` と `(139.96817980499998,39.880223054)` だったのに対し、GDBでは両方 `(139.9681798050001,39.880223054000055)` となっていました。参照は有効、GDBは無効です。これは**全国GDBの025**であり、2頂点少ない試験版025や、その後の2頂点削除候補とは分けて扱います。

保存Esri結果21件のうち、GDBをGEOSで有効としたままshort segmentsを報告していたのは024・112・131・137・148の5計画区でした。GEOS有効性だけでEsri合格を代用できません。

この比較は、参照とGDBの間で座標の区別が失われ、位相上の差が出ている直接の証拠です。ただしv0.3本体そのものとの履歴一致、変換時の内部処理、Check Geometry内部のクラスタリング機序を直接観測したものではありません。

## 空白候補13件のN03への独立照合

[audit_void_source_context.py](../../scripts/audit_void_source_context.py)で全13件を、提供N03の元地物と公開市町村GPKGへ直接照合しました。元SHP SHA-256は `6325d7f08c9374198e27b2cffd01bd420411be8b3cf3528da0587c6cea35538d` です。[全件結果](void-source-context.json)に候補ID・代表点・周辺原典地物のID/属性・面積交差・距離を保存しました。

- 全13件の代表点はN03にも公開市町村形状にも含まれませんでした。
- 全13件とも両方との面積を持つ交差は0㎡でした。境界線・点の接触による非空交差はあるので、「交差なし」とは記録しません。
- 候補部分の空白は、代表点・面積の検査範囲では、提供N03と公開市町村形状にも存在します。今回の候補作成だけで土地の面積が新規に抜けたとは判断できません。
- これは継承されたcause='原典由来'を読むだけの確認ではなく、実際の原典形状への追加照合です。ただし候補が法的にどこへ属するか、湖面かどうかはN03の属性だけでは確定できません。

原典に遡る幾何学的照合は完了しました。水域・地形・公式境界の意味は、権威ある追加資料が必要な未確認事項として残します。空白を一律に埋める根拠にはしません。

## 全国の重なり・隙間・流域整合性と採用判断

既存geometry-audit-20261013には、v0.1/v0.2の全国再集約・区域間重なり・未割当との交差・流域整合性の全件検査があります。v0.2の計画区からの再集約と流域には15/44件で非空差分が残る記録を保持します。025の局所削除案も、増加部分の大半が流域11の外側であり、原典外側の増加を伴います。

今回の全国GDBには27地物のGEOS無効があります。この形状を有効とみなして全国のunion/differenceを実行し、整合性合格を報告することはしません。修復を自動で挟めば別の形状になるため、無断の修復やエラーを隠す処理も加えません。今回は全国採用する修復候補自体が成立していません。したがって「修正後の全国候補が重なり・隙間・階層整合性に合格」は**未実施・未成立**です。

現時点の採用判断は、全国採用保留の継続です。025の2頂点削除はこの13空白候補へ一般化できず、全国共通規則にも使いません。4頂点の候補から2頂点を除くとポリゴンを維持できません。

## ArcGIS実機検査の準備と未実行事項

この環境にはarcpyがありません。元空白候補GPKG自体のEsri検査、同条件での新規GDB出力比較、全国3レイヤのEsri再検査は実行できませんでした。既存の保存結果を新規実行の結果に置き換えません。

実機用に[run_arcgis_readonly_checks.py](../../scripts/run_arcgis_readonly_checks.py)を作成しました。元GPKGを変更せず、直接のEsri Check Geometry、別の新規GDBへの固定XY設定でのエクスポート、出力のEsri検査、実測XY設定・結果表・JSON・入力ハッシュを保存します。出力フォルダが既存の場合は停止します。Repair Geometryは実行しません。

構文検査とdry-runは成功しましたが、実機実行は**未実施**です。[dry-run結果](arcgis-plan.json)にはexecuted=false・arcpy_available=falseを記録しました。

ArcGIS ProのPython環境で、スクリプトとGPKGを置いたディレクトリから次のように実行します。

```bash
python run_arcgis_readonly_checks.py --void-gpkg candidates-typed.gpkg --output arcgis_void_checks_new
```

必要に応じて `--national-gpkg` と `--comparison-gpkg` に実ファイルを追加できます。出力results.json・checks.gdb・各エクスポートJSONで実行条件と結果を確認できます。実機のエラーテーブルが地物IDのみを返す場合、これも直接問題点座標を返した証拠にはなりません。診断位置GeoJSONとの地物・座標比較は補助証拠です。
