# ArcGIS Pro 3.7.1での図形認識の確認

公開v0.2の森林GeoPackageをArcGIS Pro 3.7.1に追加すると、計画区と広域流域がスタンドアロンテーブルになりました。計画区の日本語属性と158件は読めますが、geomはBLOB列と表示されました。同梱の平面直角座標系GeoPackageは図形として描画できました。追加画面のジオメトリ欄はいずれも空欄だったため、この欄だけでは判定できません。

森林の図形列はSQLで `geom BLOB NOT NULL`、平面直角座標系は `geom MULTIPOLYGON` でした。森林もgpkg_geometry_columnsにはMULTIPOLYGONとして登録されていました。SQLite整合性、GDALでの読み込み、図形ヘッダーの検査だけでは、この認識の違いを検出できませんでした。

公開v0.2のコピーで、森林3レイヤのSQL図形列宣言をMULTIPOLYGONに変更しました。全222行の全列を比較し、図形バイナリと属性が一致すること、その他のテーブルの値も一致することを確認しています。コピーではテーブルの再構築とVACUUMも行ったため、単一要因だけを変えた試験ではありません。

利用者から受け取った画面と回答で、次を確認しました。

| 比較用レイヤ | 件数 | 図形認識・単独描画・日本語属性 |
|---|---:|---|
| 計画区 | 158 | 確認済み |
| 広域流域 | 44 | 確認済み |
| 未割当 | 20 | 確認済み |

計画区のプロパティはPolygon、Z/Mなし、JGD2011、WKID 6668、出典EPSG、角度単位は度でした。計画区の拡大縮小と、3レイヤ同時表示での拡大縮小について、利用者から異常なしと回答を受けています。この結果はSQL宣言が認識に関与することを強く支持します。

生成処理では森林3レイヤをMULTIPOLYGON宣言に変更し、配布ビルドにSQL宣言と登録型の一致検査を追加しました。BLOB宣言のまま配布しないための回帰テストも追加しました。図形の集約方法、微小リングの処理、所属判定は変更しません。
