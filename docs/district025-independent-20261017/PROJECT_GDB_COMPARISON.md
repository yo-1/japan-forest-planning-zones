# 再添付プロジェクトZIPの座標比較（2026-10-17 JST）

## 受領と範囲

利用者が再添付した「マイ プロジェクト4.zip」は1,318,469 bytes、SHA-256 `63b42259484b2e3d9e22a99e05416a68f8ec0a766187b274797991c799240f6a` でした。以前の受領記録と完全一致し、ZIPのCRC検査は正常です。ディレクトリ込み232エントリ、実ファイル220件でした。

比較用GPKGはZIP内にありません。一方、unchanged.gdb・candidate.gdbに入力地物と保存済みCheck Geometry結果があり、今回は両GDB同士の独立座標比較を完了しました。プロジェクト既定の別GDBにはユーザーレイヤを確認できず、OpenFileGDBで通常レイヤとして開けませんでした。必要な両GDBは正常に読み取れています。プロジェクト全体はローカルパス等を含むため公開しません。

## 実測

GDAL/OpenFileGDBで読み取った座標列を、丸め・スナップ・修復・再投影せず比較しました。

差があったのは0始まりring 2023だけです。未変更版からpos 54179・54180を削除した座標列と候補版が、全座標・全順序で完全一致しました。他の2,383リングも全座標・全順序が完全一致しました。これはGDBのデコード後座標比較であり、未入手の配布GPKGとのバイナリ・全座標同一性を示すものではありません。

削除された座標：

- pos 54179: `(139.9681798050001, 39.880223054000055)`
- pos 54180: `(139.9678862720001, 39.879999690000034)`

未変更版の近接組はring 2023のpos 54178・54180、距離 `7.810203469779092e-9` 度で、既存添付JSON検査の公開結果と同じです。閉点と同一リングの巡回隣接は検索から除き、別リング間も検索しました。候補版には同じ探索条件で正の近接組はなく、両版とも距離0の非隣接組は0です。旧JSON全体そのものを再受領して全座標比較したという意味ではありません。

2版間の増加部分は `1.4376017341337037e-12` 度²、減少は0です。増加部分の形状座標は既存context-result.jsonの診断増加部分と一致します。前回の原典N03照合で大半が原典外側だったという評価は引き続き必要です。

属性で異なるのは自動計算のShape_Length・Shape_Areaだけで、他の9属性は一致しました。候補にも引き継がれたoriginal_esri_problem='self intersections'が残りますが、これは元の属性であり、候補版の再検査結果ではありません。

## 保存済み検査結果と位置の限界

check_unchangedはCLASS='district025_unchanged'、FEATURE_ID=1、PROBLEM='self intersections'の1行。check_candidateは0行です。保存済みメッセージXMLは未変更版のWARNING 000442と候補版の成功を示しています。今回ArcGISを再実行したものではありません。

両チェックテーブルの列はCLASS・FEATURE_ID・PROBLEMで、自己交差の報告位置座標はありません。FEATURE_ID=1は地物の識別子で、リング・頂点の番号ではありません。局所2頂点削除以外に座標差がなく、保存結果が1行→0行だったことを確認できましたが、Esriがその切れ込みの座標を直接報告したと断定しません。内部クラスタリングの仕組みも未確認です。

## 残る不足資料

- 配布GPKGとの独立照合だけが未完了です。元ZIPが見つからなければ、内部の `district025_arcgis_comparison_20261017.gpkg` 単体で足ります（期待SHA-256 `b93f906489e5cd670be95f934d8c96fd8e98a7a079a9be666440e13c44efb4cf`）。元ZIP自体の再提出は必須ではありません。
- 報告位置の直接特定には位置情報が必要ですが、今回のCheck Geometry結果表にはありません。同じ表を再提出しても位置座標は増えません。
- その後の画面にあるvoid_candidates_gdb・check_void_candidatesはこのZIPにありません。別プロジェクトの結果として扱い、[画面観測記録](../void-candidates-20261017/observed-result.json)へ分けて保存しました。
