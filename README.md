# japan-plane-rectangular-cs-zones

日本の平面直角座標系（全国19系）の適用区域ポリゴンデータです。
国土数値情報（行政区域データ）の行政区域に平面直角座標系の系番号を割り当て、系ごとにまとめたポリゴンと、
都道府県・市町村と系番号の対応データをまとめて提供することを目指しています。

> **ここまで進んでいます**: 19系の定義（`data/zones.csv`）と、系番号を判定するルール（`data/zone_rules.csv`）を
> 用意できました。都道府県・市町村との対応表や、ポリゴンデータ、生成スクリプトはこれから追加していきます。

## 収録データ

### `data/zones.csv` — 19系の定義

平面直角座標系（平成十四年国土交通省告示第九号）の表をそのまま書き写したものです。文字コードはUTF-8（BOMなし）、改行はLFです。

| 列名 | 内容 |
|---|---|
| `zone` | 系番号（1〜19） |
| `zone_roman` | 系番号のローマ数字表記（I〜XIX） |
| `origin_lon_dms` / `origin_lat_dms` | 座標系原点の経度（東経）・緯度（北緯）。告示の値（度分秒） |
| `origin_lon` / `origin_lat` | 同じ値を10進数で表したもの（度） |
| `epsg_jgd2011` | 対応するEPSGコード（JGD2011、EPSG:6669〜6687） |
| `area_text` | 告示にある「適用区域」の文言 |

- 原点と適用区域は、国土地理院のページ「平面直角座標系（平成十四年国土交通省告示第九号）」
  https://www.gsi.go.jp/LAW/heimencho.html （最終改正 平成二十二年三月三十一日国土交通省告示第二百八十九号）から書き写しました。
- `epsg_jgd2011`は告示には出てきません。原点の経緯度と縮尺係数0.9999がEPSGの定義と一致することを、
  pyprojのEPSGデータベースで確認しています（`tests/test_zones_csv.py`）。
- `area_text`は人が読むための文章です。系番号を実際に判定するときは`data/zone_rules.csv`を使います。

### `data/zone_rules.csv` — 系番号の判定ルール

告示にある適用区域を、元データ（行政区域データ）の属性と経緯度から判定できる形に書き直したものです。
UTF-8（BOMなし）、改行はLFです。

| 列名 | 内容 |
|---|---|
| `rule_id` | ルールの番号。この順番で評価し、最初に条件が合ったルールを採用します |
| `zone` | 系番号 |
| `prefecture` | 都道府県名（N03_001と照合） |
| `subprefecture` | 北海道の振興局名（N03_002と照合） |
| `county` | 郡名（N03_003と照合） |
| `municipality` | 市区町村名（N03_004と照合） |
| `lon_min` / `lon_max` / `lat_min` / `lat_max` | 代表点の経度・緯度の範囲（度、JGD2011）。両端を含みます |
| `basis` | 告示のどの部分に基づくか（要約） |
| `note` | 補足や、こちらで置いた仮定 |

- 欄が空のときは「条件なし（どの値でも一致）」という意味です。
- 告示にある「〜を除く」という書き方は、ルールを上から順に評価することで表しています。例えば東京都の場合、
  先にXIV系・XVIII系・XIX系に当てはまるかどうかを確認し、どれにも当てはまらなければIX系、という順番です。
- 境界線上ぴったりの点は複数のルールに当てはまりますが、その場合は`rule_id`が小さい方を優先します
  （例：東経143度ちょうどはXIV系になります）。
- 判定処理は`scripts/zone_rules.py`に書いています（標準ライブラリだけで動きます）。

**まだ仮定のままの点・確認できていない点**

- 経緯度で判定するルールは、「ポリゴンの中の1点（代表点）がどこにあるか」で系を決める前提です。もし1つの
  ポリゴンが境界（北緯28度や東経126度・130度など）をまたいでいたら、この方法では正しく判定できません。
  生成するときにそういうケースがないか確認する予定です。なお、元データで島が1つずつポリゴンに分かれて
  いるかどうかは、まだ確認できていません。
- 鹿児島県の「奄美群島」は、大島郡と奄美市とみなして扱っています（こちらで置いた仮定です）。
- 振興局名・市町村名・郡名の表記が元データの値ときちんと一致するか（例:「後志総合振興局」）は、
  元データ側でまだ確認できていません。

### 注意していただきたいこと

平面直角座標系の適用区域は、多くは都道府県・市町村・振興局の単位で決まっていますが、
次の都県だけは経緯度の範囲で決まっています（告示より）。

| 都県 | 系 | 区分の基準 |
|---|---|---|
| 鹿児島県 | I・II | 北緯27〜32度、東経128度18分〜130度（奄美群島は130度13分まで）の範囲内にある島はI系、それ以外はII系 |
| 東京都 | IX・XIV・XVIII・XIX | 北緯28度より南の部分を、東経140度30分と143度で区分。それ以外はIX系 |
| 沖縄県 | XV・XVI・XVII | 東経126度と130度で区分 |

この3都県では同じ市町村の中でも系番号が分かれることがあり、市町村単位の対応表だけでは
系番号を1つに決められない場合があります。該当する区域の扱いは、データを追加するタイミングでこの
READMEに書き足します。

北海道は、振興局の所管区域と一部の市・町の単位でXI〜XIII系に分かれます。

座標の測量・設計などに使う場合は、国土地理院の資料と根拠となる法令（座標系の告示）で、必ず適用区域を
確認してください。

### 元データについての注意（出典URLのページの「その他の情報」より）

- 一部の市区町村には境界が決まっていない地域があり、元データでは境界線が暫定的に引かれています。
  このリポジトリのポリゴンも、その暫定境界線をそのまま引き継いでいます。境界が決まっていない地域の詳細は、
  該当する市区町村に確認してください。
- 東京都千代田区・中央区・港区の境界と、東京都中央防波堤埋立地は、元データ側で修正が行われています。

### 使用する元データの属性

元データ（行政区域データ2026年版）の属性のうち、次のものを使う予定です。属性名の後ろの括弧内は
シェープファイルでの属性名です。

| 属性名 | 用途 |
|---|---|
| 都道府県名（N03_001） | 系番号の割り当て |
| 北海道の振興局名（N03_002） | 北海道内での系番号の割り当て |
| 郡名（N03_003） | 表示用 |
| 市区町村名（N03_004） | 系番号の割り当て |
| 政令指定都市の行政区名（N03_005） | 表示用 |
| 全国地方公共団体コード（N03_007） | 対応表のキー |

全国地方公共団体コードは、元データの定義では任意項目（多重度0..1）です。コードが空のポリゴンを
どう扱うかは、データを追加するタイミングでこのREADMEに書き足します。

## テスト

リポジトリのルートで実行します（Python 3.9以降を想定。標準ライブラリだけで動きます）。

```bash
python -m unittest discover -s tests -v
```

pyprojが入っていない環境では、EPSGの定義と照合するテストはスキップされます（未実行として扱ってください）。

`tests/test_zone_rules.py`にある地点ごとの期待値は、告示の適用区域から導いたものです。代表点の経緯度は
おおよその位置で、元データとの照合はまだ行っていません。
