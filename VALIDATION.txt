2026-10-04  東京都・鹿児島県・沖縄県のポリゴンが系の境目をまたぐか
----------------------------------------------------------------------

実行した環境（ユーザーの PC）
  - Windows、QGIS 3.44 に付いている OSGeo4W Shell、Python 3.12.13
  - スクリプト: scripts/check_coordinate_zones.py（main ee943e4 の版）
  - 元データ: 国土数値情報（行政区域データ）2026年版 N03-20260101.shp / .dbf
    （N03-20260101_GML.zip を展開したもの）

結果
  - 書き出した件数: 21,786件（東京都 6,904、鹿児島県 9,022、沖縄県 5,860）。
    .dbf の3都県の行数と一致した。
  - 境目をまたぐ候補: 0件。3都県のすべてのポリゴンの系が決まった。

  都県ごとの系の件数

    鹿児島県  I系 3,434   II系 5,588
    沖縄県    XV系 3,231  XVI系 2,568  XVII系 61

  1つの市町村の中で系が分かれたもの（書き出した CSV から集計。範囲は概数）
    東京都 小笠原村     XIV系 4,794  XVIII系 7（沖ノ鳥島付近）  XIX系 11（南鳥島付近）
    鹿児島県 薩摩川内市 I系 659（東経129.66〜129.99、甑島）  II系 71
    鹿児島県 南さつま市 I系 492（東経129.42〜129.48、北緯30.83〜31.22）  II系 677

  .dbf との突き合わせ
    - 東京都の XIV・XVIII・XIX 系の合計 4,812件は、小笠原村の行数と一致した。
      所属未定地 123件を含め、小笠原村以外はすべて IX系。
    - 沖縄県の XVI系 2,568件は、石垣市・宮古島市・与那国町・竹富町・多良間村の行数の合計と一致した。
      XVII系 61件は、北大東村と南大東村の行数の合計と一致した。
    - 鹿児島県の所属未定地 12件は、すべて I系（東経129.73〜129.74）。
    - 喜界町には東経130度より東の島が7件あるが、奄美群島の規定（東経130度13分まで）により I系になった。

  境目の近くにあるポリゴン
    - 範囲を 0.0001度（約10m）広げても、またぐ候補は0件だった。
    - 0.001度（約100m）広げると、薩摩川内市の小さな島3件が東経130度にかかる。
      どれも東経130.0003〜130.0014度にあり、東経130度より東なので II系になっている。
      告示の「東方東経130度を境界線とする区域内」に入らないので、判定としては正しいと考えている。

  そのほか
    - 1つの行が複数の部分（パート）でできているポリゴンが7件あった
      （町田市、小金井市、武蔵村山市、出水市、志布志市、大崎町、石垣市）。
      穴のあるポリゴンか、複数の島をまとめたものかは未確認。どれも境目はまたいでいない。

未確認
  - 「またぐ候補」は範囲（最小・最大の経緯度）で見た結果。範囲がまたがなければポリゴンもまたがないので、
    今回の0件は確実。ただし、形そのもの（頂点）は見ていない。
  - 十島村の II系 33件（東経130.05〜130.07）がどの島かは、地図では確かめていない。
  - 奄美群島を「大島郡と奄美市」とみなす仮定が、法令などの資料と合っているか。

2026-10-04  対応表 data/municipality_zones.csv の作成
----------------------------------------------------------------------

作り方
  - Claude Code の環境（Linux）で、scripts/build_zone_data.py の割り当て処理（assign_zones）を使って作った。
  - 入力は、元データの N03-20260101.dbf（ユーザーから受け取ったもの）と、ユーザーの PC で
    check_coordinate_zones.py が書き出した coordinate_zones.csv の範囲（東京都・鹿児島県・沖縄県の21,786件）。
    .shp そのものは Claude Code の環境にないため、範囲はこの CSV から取った。

結果
  - ポリゴン125,130件すべてに系番号が付いた。全国地方公共団体コードは1,905件。
  - 3都県の系番号は、ユーザーの PC での実行結果（coordinate_zones.csv の zone 列）と全件一致した（食い違い0件）。
  - 系ごとのポリゴンの数（I系〜XIX系）:
      12,642 / 15,494 / 7,345 / 13,451 / 3,297 / 15,881 / 3,858 / 4,643 / 6,245 / 22,046 /
      5,273 / 1,613 / 2,670 / 4,794 / 3,231 / 2,568 / 61 / 7 / 11
  - 系が分かれるのは5件（小笠原村 14;18;19、薩摩川内市・南さつま市・三島村・十島村 1;2）。
  - ZONE 列を足した .dbf を実際の元データで書き出し、別の読み込みライブラリ（pyshp）でも正しく読めることを確かめた
    （125,130行、列の定義と ZONE の値が一致）。

未確認

  - ZONE 列付きのシェープファイルを QGIS で開けること、QGIS でのディゾルブの手順と所要時間。

2026-10-04  ユーザーの PC で build_zone_data.py を実行し、QGIS でディゾルブ
----------------------------------------------------------------------

実行した環境（ユーザーの PC）
  - Windows、QGIS 3.44.11-Solothurn、Python 3.12.13、GDAL 3.13.0、GEOS 3.14.1、PROJ 9.8.1
  - スクリプト: scripts/build_zone_data.py（main d58b362 の版）
  - 元データ: N03-20260101.shp / .dbf（2026年版）

build_zone_data.py の結果
  - ポリゴン 125,130件、市区町村など 1,905件。
  - 系ごとのポリゴンの数と、系が分かれる5件の市町村は、上の「対応表の作成」の記録と全件同じだった。
  - 書き出した N03-20260101_zone.shp を QGIS で開き、属性テーブルに ZONE 列があること、
    地物数が 125,130件であることを確かめた（画面で確認）。

QGIS のディゾルブ（ベクタ → 空間演算ツール → ディゾルブ、基準の属性は ZONE）
  - 所要時間: 101.60秒。エラーなし（「ジオメトリの修復」は使っていない）。
  - 出力: GeoPackage、地物数 19、ジオメトリは MultiPolygon、座標系 EPSG:6668（JGD2011 の緯度経度）。
  - 範囲: 東経 122.93〜153.99、北緯 20.42〜45.56。
  - ファイルの大きさ: 163.97MB。
  - 地図で見て、北海道・本州などの中に系の境目が引かれていることを確かめた（画面で確認）。

気づいたこと
  - ディゾルブの結果には ZONE のほかに N03_001〜N03_007 の列が残る。系ごとにまとめた行に、たまたま
    残った1つのポリゴンの値が入っているだけなので、配るときは消す必要がある。
  - 163.97MB は、GitHub のリポジトリに入れられる1ファイルの上限（100MB）を超える。

未確認
  - ディゾルブの結果のジオメトリが正しいか（QGIS の「妥当性をチェック」はまだかけていない）。
  - 系ごとのポリゴンの面積や、隣の系との間にすき間や重なりがないか。

build_zone_data.py の結果
  - ポリゴン 125,130件、市区町村など 1,905件、系ごとの数と系が分かれる5市町村は、前の記録と同じだった。
  - 表示された「ディゾルブ後の地物の数（予想）」は、系ごと 19件、都道府県ごと 392件、市区町村ごと 1,911件。
  - QGIS の属性テーブルで、5列が入っていることを確かめた（例：札幌市中央区 XII / 6680 / 01101 / 札幌市中央区、
    函館市 XI / 6679 / 01202 / 函館市）。

ディゾルブ（ベクタ → 空間演算ツール → ディゾルブ）
  基準の属性           所要時間   地物数（予想と一致）
  ZONE                  88.06秒   19
  ZONE, UNIT_CODE       64.52秒   392
  ZONE, N03_007         34.18秒   1,911
  - どれも MultiPolygon、EPSG:6668、範囲は東経 122.93〜153.99、北緯 20.42〜45.56。

列を残して保存（プロセッシングツールボックスの「属性を選択保持」）
  - plane_rectangular_zones_2026.gpkg：fid、ZONE、ZONE_ROMAN、EPSG（19件）
  - plane_rectangular_prefectures_2026.gpkg：fid、N03_001、N03_002、ZONE、ZONE_ROMAN、EPSG、UNIT_CODE、UNIT_NAME（392件）
  - plane_rectangular_municipalities_2026.gpkg：fid、N03_001〜N03_005、N03_007、ZONE、ZONE_ROMAN、EPSG（1,911件）
  - 属性テーブルで値を確かめた（画面で確認できた範囲）。府県の行はコードが府県コード＋000（例：富山県 16000、京都府 26000）、
    4都道県の行は市区町村のまま（例：東京都の各区、北海道の泊村）。東京都の所属未定地（13000）は IX系。
  - 保存先のファイル名を貼り付けたときに改行が混ざり、保存に失敗したことがあった（手で入力し直して解決）。

ジオメトリの妥当性（ベクタ → ジオメトリツール → ジオメトリ妥当性、GEOS の方式）
  zones          有効 19     無効 0  エラー 0
  prefectures    有効 392    無効 0  エラー 0
  municipalities 有効 1,911  無効 0  エラー 0

  - 保存のあと、都道府県ごと・市区町村ごとが地図に表示されなくなった（属性テーブルも0件と表示）。
    フィルタはかかっておらず、ファイルは正常（地物数 1,911、243.51MB）。QGIS を開き直して読み込み直すと、
    保存したスタイルで表示された。原因は、QGIS の中で読み込みの状態が古いまま止まっていたためと推定（未確認）。
